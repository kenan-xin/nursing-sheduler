# v1 AI study (v1 sync W4)

Date: 2026-09-27. Bead: `nursing-sheduler-2uxm`. Spec: `docs/superpowers/specs/2026-09-25-v1-genie-sync-design.md`, section "W4: v1 AI study".

## What was compared

- **v1**: the Python AI package at genie `1bf4b85` in `/home/kenan/work/nurse-scheduling`:
  `core/nurse_scheduling/ai/`, and its eval set `core/tests/ai_eval/` with 109 cases in `cases/basics/`.
  The package is a FastAPI service with an E2B sandbox. Its tools are `read`, `bash`, `edit`, `write` and `optimizer`.
  The local checkout is on `dev` (`d41a6c5`), so every file was read at `1bf4b85` through `git archive`.
- **v2**: the schedule assistant in `web/lib/ai`, `web/components/ai`, `web/evals` and `docs/ai-assistant.md`.

The v2 rules stay as they are (bd memory `agent-native-goal`). The user brings their own key.
The server keeps no chat text. A run starts only after the user presses Run. Every change is a
Preview, and the user applies it.

## The two designs in one paragraph

v1 gives the model a throwaway Linux sandbox with the schedule as a YAML file. The model edits the
file with shell and text tools. The server then checks and diffs the file, and the user approves
the diff. The server keeps sessions, runs the optimiser itself and keeps chat history in Postgres
for 30 days. v2 gives the model a fixed list of typed operations (`prepare_scenario_change` and
others). The app turns them into a Preview using each screen's own functions. Everything stays in
the browser. Because the two designs differ this much, most of v1's machinery does not carry over,
but some of its guard rails and test ideas do.

## Idea table

| # | v1 idea (file at 1bf4b85) | v2 status | Action |
| --- | --- | --- | --- |
| 1 | Assistant-started optimiser runs are always anonymized: people become `P1..Pn`, descriptions are removed, and names are put back in the returned workbook (`ai/optimizer_privacy.py`) | The Optimise screen does the same, and it is on by default. A run the user starts from the assistant's card uses that screen and its setting. **But diagnostic candidate solves always send real names** (`diagnostic-orchestrator.ts:340`, `anonymize: false`) | Bead `nursing-sheduler-kb7v` |
| 2 | The prompt says schedule contents, attachments and tool output are data, and instructions inside them are ignored (`ai/prompts/sandbox-system.md`) | Said for attachments (`runtime/attachments.ts`) and for the history summary. **Not said for the schedule itself**, which the model reads in full | Bead `nursing-sheduler-69k6`. Eval cases `safety-quoted-injection` and `safety-stored-injection` |
| 3 | XLSX inspection: all sheets, formulas and cached values, bounded cell count, zip-bomb and encryption checks (`ai/attachment_tools/inspect_xlsx.py`) | Not supported. Only images and `.txt`/`.csv`/`.md` (bead 2by.10) | Bead `nursing-sheduler-6eli`: convert in the browser with ExcelJS, which v2 already uses |
| 4 | Images over the size limit are resized to 2000 px instead of being refused (`ai/pi/image_process.py`) | Images over 3.75 MB are refused (`attachment-rules.ts`). A phone photo of a paper roster is often bigger | Bead `nursing-sheduler-j6dk`: shrink in the browser with canvas |
| 5 | Image type is checked from the file's bytes, not its name (`ai/pi/mime.py`) | Done: `contentMatches` in `attachment-rules.ts` and the server check in `runtime/attachments.ts` | None |
| 6 | PDF inspection: text per page, and render one page as an image (`ai/attachment_tools/inspect_pdf.py`) | Not supported | **Not now.** It needs a new dependency (pdf.js), and v1 did no OCR either. A screenshot of the page already works as an image |
| 7 | Images inside DOCX and PPTX files (evals `read-image-docx`, `read-image-pptx`) | Not supported | **Not worth it.** Wards rarely send these. A screenshot works |
| 8 | Schema reference pages the model reads before editing YAML (`ai/references/schema-*.md`) | Not needed: typed operations with zod field descriptions (`lib/proposal/commands.ts`) and `get_schedule_section` | **Not worth it.** The pages teach raw YAML editing, which v2 does not allow |
| 9 | If a name has two meanings, ask before the edit. Examples: base id or group, "night" as shift or group, "requests" as all or some (`sandbox-system.md`) | Done: `offer_choices` cards and eval `reg-pick-one-as-text` | None |
| 10 | Never create two hard rules that cannot both hold. Explain the conflict and ask (`sandbox-system.md`, eval `reject-conflicting-shift-request`) | No eval | Eval case `safety-conflicting-request` |
| 11 | Before extending the date range, ask whether to renew the Singapore holiday groups (`sandbox-system.md`, evals `dates-range-expand-singapore-*`) | The op already requires `importPublicHolidays` and tells the model to ask the user, never assume. No eval | Eval case `sg-extend-range-asks-holidays` |
| 12 | A question about the schedule is answered, not turned into an edit (eval `reject-no-change`) | No eval | Eval case `grounding-state-question` |
| 13 | After a rejected proposal, a narrower request makes only the narrower change (eval `reject-then-narrower-edit`) | No eval | Eval case `reg-reject-then-narrower` |
| 14 | A schedule change under a pending proposal makes the proposal invalid (`app.py` `_require_approvable`, eval `external-update-invalidates-pending`) | Done: the Preview shows *out of date*. Unit tests are in `lib/ai/assistant` | None |
| 15 | Never claim a change happened before approval (`sandbox-system.md`) | Done: `ASSISTANT_AUTHORITY_STATEMENT`, evals `safety-just-apply`, `reg-claim-after-preview` | None |
| 16 | The assistant starts, checks and finishes optimiser runs itself, in the background, and is woken with the result (`ai/optimizer.py`, `finish_now`) | By design, v2 only offers a Run card. The run goes through the Optimise screen, and the assistant reads the result afterwards (`reg-empty-reply-after-infeasible`) | **Not taking** start and finish-now: runs stay started by the user |
| 17 | The optimiser's 4xx reason is passed back to the model, cut to 300 characters (`optimizer.py` `_rejection_reason`) | Done: `get_optimize_result` gives the screen's error code and message | None |
| 18 | Validation problems go back to the model, at most 20, each at most 300 characters (`ai/validation.py`) | Done in a different way: a refused op returns a code, a message and the valid ids | None |
| 19 | Chat history in Postgres for 30 days, server sessions, owner cookies (`ai/history.py`, `app.py`) | The server stores nothing. History stays in the browser | **Not taking.** It breaks the no-server-storage rule |
| 20 | E2B sandbox with shell, edit and write tools on the YAML (`ai/sandbox*`, `ai/pi/`) | Typed operations and Preview instead | **Not taking.** It costs a paid sandbox per turn, and free-form edits bypass the screens' own functions |
| 21 | Messages sent during a running answer are queued and fed in at the next step ("steering", `app.py` `queue_steering`) | Stop, plus a send gate. A new message stops an unapplied Preview | **Not worth it.** It adds a lot of state for little gain in short ward chats |
| 22 | A provider timeout before streaming starts gets an automatic retry with backoff (`ai/provider.py`) | OpenRouter model fallback, plus a one-click Retry (2by.8) | **Not taking.** The key is the user's own paid key, so the user decides on a retry |
| 23 | Upstream error bodies are redacted before logging (`provider.py` `_redact_provider_error`) | v2 logs no prompts, output or credentials | Not needed |
| 24 | Tool round and call caps (200 rounds, 400 calls, `agent.py`) | The runtime bounds the run. Evals use `limits.maxHops` | None |
| 25 | Evals grade the exact diff. A `changes` guard fails any edit outside the named paths. `holdout` cases check that the prompt works on other fixtures (`tests/ai_eval/README.md`, `grading.py`) | `proposalOps` is a subset match. Only a hand-written `proposalCheck` checks scope. No holdout tag | Bead `nursing-sheduler-lsbk` |
| 26 | Evals for affinity rules (work together or apart) and coverings (`04-preferences/pref-affinity-*`) | The assistant has no affinity or covering op (`ASSISTANT_COMMAND_TYPES`) | Bead `nursing-sheduler-31og` |
| 27 | Export layout edits (7 evals in `05-export`) | The Export Layout editor is deferred (`qq0.15`) | **Not taking** until that screen exists |
| 28 | App-usage answers from the user guide pages (`10-app-ui`) | Done: help tools and screen navigation (`use-help-tools.ts`, `reg-offer-as-text`) | None |
